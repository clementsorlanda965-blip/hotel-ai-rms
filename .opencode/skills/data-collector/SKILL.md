## 强制规则

所有文字输出必须是中文。数据字段以中文标注。输出到 `outputs/` 目录。文件生成后自动打开。

## 管线总览

```
用户说"爬XX数据" / "采集XX信息"
  │
  ▼
Phase 1 ▸ 需求分析
  问清：来源URL / 采集字段 / 输出格式(JSON/Excel)
  │
  ▼
Phase 2 ▸ 采集
  加载 web-scraper ← Firecrawl引擎：单页/批量/搜索 + 结构化提取
  │
  ▼
Phase 3 ▸ 清洗
  去重、字段映射（中文标注）、格式统一
  │
  ▼
Phase 4 ▸ 输出
  JSON → outputs/ 或 Excel（调用 document-excel 加格式/图表）→ 自动打开
  │
  ▼
Phase 5（可选）▸ 持续
  ruflo 定时任务："每天爬一次"
  │
  ▼
输出：结构化数据文件 + 采集报告
```

## 阶段一：需求分析

**目标：** 明确采集需求，避免无效抓取。

1. 与用户确认以下信息：
   - **来源**：目标 URL 或搜索关键词
   - **字段**：需要提取哪些数据（如酒店名称、价格、评分、房型）
   - **格式**：JSON 还是 Excel
   - **频次**：一次性采集还是定期监控

2. 评估可行性：
   - URL 是否可访问？
   - 是否有反爬机制？
   - 是否在 Firecrawl 免费额度内（500次/月）？

**检查点：** 是否明确了采集范围？是否确认了输出格式？

## 阶段二：采集

**目标：** 从目标网页提取结构化数据。

1. 加载 `web-scraper` skill
2. 根据需求选择采集方式：

   | 方式 | 适用场景 | 参数 |
   |------|---------|------|
   | 单页抓取 | 特定页面数据 | URL |
   | 批量爬取 | 列表页+详情页 | URL + limit（≤20） |
   | 搜索采集 | 热门话题/关键词 | 关键词 + limit |
   | 结构化提取 | 特定字段提取 | URL + 字段定义 |

3. 执行采集，检查数据质量（字段是否完整、格式是否正确）

**检查点：** 数据是否完整？字段是否正确映射？

## 阶段三：清洗

**目标：** 确保数据一致性、可用性。

1. 去重：删除重复行
2. 字段映射：英文→中文标注（如 `price` → `价格`）
3. 格式统一：数字、日期、百分比等标准化
4. 缺失值处理：标记缺失字段，不随意填充

**检查点：** 数据是否干净？所有字段都有中文标注？

## 阶段四：输出

**目标：** 按用户需求格式输出并自动打开。

### JSON 输出

```json
{
  "meta": {
    "采集时间": "2026-05-17 10:00",
    "数据来源": "携程",
    "数据条数": 10,
    "字段列表": ["酒店名称", "房型", "价格", "评分"]
  },
  "data": [...]
}
```

### Excel 输出

1. 加载 `document-excel` skill
2. 写入结构化数据到 Excel
3. 添加格式化：冻结首行、自动列宽、条件高亮（如最低价标绿）
4. 如有历史数据，生成趋势图

**检查点：** 文件是否已自动打开？数据与采集结果一致？

## 阶段五：持续监控（可选）

**目标：** 建立定时采集任务。

1. 加载 `ruflo-automation` skill
2. 配置定时采集参数：
   - 频率：每天/每周
   - 目标：同一 URL/关键词
   - 触发条件：价格变动/新增条目
3. 用户确认后派发后台 worker

**检查点：** 定时任务是否已启动？


## 边界情况

| 场景 | 处理方式 |
|------|---------|
| URL 无法访问 | 尝试其他入口（搜索替代），或告知用户 |
| 采集结果为空 | 检查 CSS 选择器/字段定义是否正确 |
| 频率超限（Firecrawl） | 切换到 WebFetch 降级方案 |
| 数据含隐私信息（PII） | 调用 aidefence_scan 扫描并提醒用户 |
| 用户未指定输出格式 | 默认 JSON，询问是否要转 Excel |
